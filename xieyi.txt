目前 Windsurf 这个平台在我的管理后台里已经支持这些操作，全部可以一键触发：

纯协议注册 — 不开浏览器，邮箱验证码走完注册

浏览器自动注册 — 优先用 Camoufox 跑真实浏览器页面流程，失败再回退到 Playwright

Pro Trial 链接生成 — 过 Turnstile 验证码后调 protobuf 接口拿 Stripe 支付链接，纯协议和浏览器两种模式

桌面端账号切换 — 两条请求，不用重启 IDE，不弹浏览器

其中桌面端切换是最近刚搞定的，也是这篇重点讲的部分。前面几个简单带过，主要聊逆向过程。

一、注册和 Pro Trial：先把前置流程打通
注册
Windsurf 的注册比 Kiro 友好太多。它走的是自家的 JSON 接口，不像 Kiro 那样要跳四个域名、带 CBOR 二进制协议和 PKCE。

核心就三步：

POST /_devin-auth/email/start — 发送邮箱验证码

POST /_devin-auth/email/complete — 提交验证码，拿到 session token

POST WindsurfPostAuth — 用 session token 完成账号初始化

没有指纹检测，没有 workflow 状态机，protobuf 编解码也不复杂。我先在 Windsurf 里把 HAR 过了一遍，整体方向很快就清楚了，中间主要是调了几个 protobuf 字段顺序的问题。

除了纯协议，还做了一套浏览器自动注册。实现上是优先走 Camoufox，只有 Camoufox 不可用或者流程失败时才回退到 Playwright。两种方式都能用，在前端选执行器类型（protocol / headless / headed）就行。

Pro Trial 链接生成
注册完的账号是 Free 计划，想白嫖 Pro Trial 需要生成一个 Stripe 支付链接。这块也是纯协议搞定的：

调 CheckTrialEligibility（protobuf）— 确认账号有没有 Trial 资格

调 SubscribeToPlan（protobuf）— 带上 Turnstile token，拿到 Stripe checkout URL

Turnstile 验证码的解法有两种：纯协议模式下跑本地 solver（起一个 Camoufox/patchright 服务自动过验证），浏览器模式下直接在页面里点 Turnstile iframe checkbox

纯协议模式的验证码走的是项目里的 local_solver——在本地起一个无头浏览器服务，专门帮你解 Turnstile，解完把 token 返回来塞进 protobuf 请求里。不是调第三方打码平台（虽然也支持 2captcha / capsolver 作为 fallback）。

这条路跑起来还算顺，主要就是 protobuf 的 field number 要对上，把 HAR 里的 request/response 二进制对着看就行。

二、桌面端切换：这才是硬骨头
前面的注册和 Trial 其实不难，因为都是标准的 HTTP 接口。桌面端切换就不一样了——你要让一个正在运行的 Electron 应用切换到另一个账号，这不是发个请求就完事的。

第一个念头：直接改数据库
我先在 Windsurf 里找认证信息存在哪。它一开始猜的 storage.json，里面全是 UI 配置，没有 token。

继续翻，找到了一个 SQLite 数据库：


~/Library/Application Support/Windsurf/User/globalStorage/state.vscdb

里面有个 key 叫 windsurfAuthStatus，值是 JSON，里头有 apiKey: "devin-session-token$<JWT>"。看起来很简单对吧？直接 sqlite3 把 apiKey 换了不就行了？

试了，换完重启 Windsurf——没有任何变化。

翻数据库发现 Windsurf 真正的 session 藏在 secret:// 打头的 key 里：


secret://{"extensionId":"codeium.windsurf","key":"windsurf_auth.sessions"}

这玩意是 Electron 的 safeStorage API 加密的，密钥在 macOS Keychain 里。读出来全是乱码，改了直接报错。

那全删呢？把加密 key 都删了：


conn.execute("DELETE FROM ItemTable WHERE key LIKE 'secret://%windsurf_auth%'")

conn.execute("DELETE FROM ItemTable WHERE key LIKE 'windsurf_auth-%'")

重启后 Windsurf 倒是弹了登录框——然后把你踢到浏览器走 OAuth，还是得手动操作。走不通。

转向：抓包分析 OAuth 流程
既然直接改文件不行，那就搞清楚 Windsurf 登录的时候到底干了什么。

在 Windsurf 里退出登录 → 重新登录 → 浏览器抓包 → 导出 HAR → 然后继续在 Windsurf 里往下梳理整个登录链路。

最后梳理出来的登录流程大概是这样：


Windsurf IDE

→ 浏览器打开 windsurf.com/editor/signin?redirect_uri=windsurf://codeium.windsurf&...

→ 用户登录

→ 跳转到 /editor/auth-success

→ 前端 JS 调 GetOneTimeAuthToken API，用 session token 换一个一次性 token（OTT）

→ 拼 deep link: windsurf://codeium.windsurf#state=xxx&access_token=ott$xxx

→ window.location.assign(deep_link)

→ 系统 URI Handler 把 OTT 传给 Windsurf 桌面端

→ 登录完成

关键发现：Windsurf 不是直接传 session token，而是多了一层 OTT 换手。

从 HAR 里定位 GetOneTimeAuthToken
在 HAR 里找到了这个请求：


POST /_backend/exa.seat_management_pb.SeatManagementService/GetOneTimeAuthToken

Content-Type: application/proto

请求体：protobuf field 1 = devin-session-token$<JWT>

响应体：protobuf field 1 = ott$<一串 base64>

这个 API 就是把长期 session token 换成一个短命的一次性 token。

光靠 HAR 不够——还得看前端 JS
HAR 能看到 HTTP 请求，但看不到前端怎么拼 deep link。参数名叫 token 还是 access_token？用 ? 还是 # 拼接？这些 HAR 里没有。

所以后面我又直接在 Windsurf 里拉了 windsurf.com 的 JS bundle 看前端逻辑，最后从几个 chunk 里翻到了关键代码：


// 注册的 URI scheme

let n="windsurf://", a="windsurf-next://", l="windsurf-insiders://"

// auth-success 页面拿到 OTT 后的处理

h().then(t => {

y(e += "&access_token=" + t) // 参数名是 access_token，不是 token！

})

window.location.assign(p) // 跳转 deep link

// 用 # 还是 ? 取决于 redirect_parameters_type

"fragment" === n ? "#" : "?" // fragment 模式用 #

到这里，deep link 的完整格式确认了：


windsurf://codeium.windsurf#state=xxx&access_token=ott$xxx

最终实现：两条请求搞定
整个切换逻辑就两步：


# 第一步：session token → OTT

raw = client._proto_post("GetOneTimeAuthToken", _field_string(1, api_key))

ott = raw[2 : 2 + raw[1]].decode("utf-8")

# 第二步：打开 deep link

deep_link = f"windsurf://codeium.windsurf#state=switch&access_token={quote(ott, safe='')}"

subprocess.run(["open", deep_link])

执行后 Windsurf 弹一个确认框：“Are you sure you want to log in using a different account?”，点 Yes 就切换完了。

不到 1 秒，不弹浏览器，不用重启。

三、踩过的坑
改 JSON 没用 — windsurfAuthStatus.apiKey 只是个缓存，真正的 session 在加密的 secret:// key 里，Electron safeStorage + macOS Keychain 双重保护，动不了。

deep link 参数名搞错 — 我一开始用的 #token=<OTT>，Windsurf 报 invalid auth token。翻了 JS 源码才知道正确的参数名是 access_token。一个单词的区别，调了半天。

protobuf 解析偏移 — OTT 响应的格式是 0x0a <varint_length> <string>。一开始搞混了 varint 长度和字符串内容的边界，解析出来的 OTT 少了或多了字节，传给 Windsurf 当然报错。

OTT 一次性 — GetOneTimeAuthToken 返回的 OTT 只能用一次。debug 的时候我拿 OTT 打了个日志，然后再用同一个 OTT 开 deep link，结果 unauthenticated。白白浪费了时间。

四、和 Kiro 对比一下
| | Kiro (AWS Builder ID) | Windsurf |

|—|—|—|

| 协议 | CBOR 二进制 | Protobuf 二进制 |

| 认证链路 | 4 个域名跳转 + workflow 状态机 | 1 个 API + deep link |

| 指纹检测 | ECdITeCs: 浏览器指纹，严格校验 | 没有 |

| PKCE | S256 | 没有 |

| 纯协议能不能走通 | 卡在 fingerPrint，走不通 | 全部走通 |

| 逆向工具 | Kiro 逆向 Kiro | Windsurf 逆向 Windsurf |

坦白讲 Windsurf 的逆向比 Kiro 简单一个数量级。Kiro 背后是 AWS 那一套企业级安全体系，纯协议在 fingerPrint 那一步就卡死了。Windsurf 没有指纹、没有 PKCE、没有 CSRF，整个 OTT + deep link 的设计其实挺优雅的，只是没有公开文档。

五、目前 Windsurf 平台的完整能力
| 功能 | 方式 | 说明 |

|—|—|—|

| 注册 | 纯协议 / 浏览器 | 纯协议走 /_devin-auth/email/* JSON 接口，浏览器模式优先 Camoufox，失败再回退到 Playwright |

| 查询账号状态 | 纯协议 | GetCurrentUser protobuf 接口，拉计划类型、额度、到期时间 |

| 检查 Trial 资格 | 纯协议 | CheckTrialEligibility |

| 生成 Pro Trial 链接 | 纯协议 / 浏览器 | 纯协议用本地 solver 过 Turnstile，浏览器在页面直接点击过验证，拿 Stripe 支付链接 |

| 桌面端账号切换 | 纯协议 | GetOneTimeAuthToken → windsurf:// deep link |

对应的代码结构：


platforms/windsurf/

├── core.py # protobuf 编解码 + API 客户端

├── protocol_mailbox.py # 纯协议注册

├── browser_register.py # 浏览器自动注册 / Trial / 支付流程（优先 Camoufox，回退 Playwright）

├── switch.py # 桌面端切换（OTT + deep link）

└── plugin.py # 插件入口，注册所有 capabilities

整个项目是插件化架构，每个平台一个 plugin，capabilities 统一注册。加新平台就是加一个目录，不用动框架代码。

六、方法论（简单说几句）
“用 X 逆向 X” 这事的套路其实很固定：

抓包 — 关掉无关软件，只留目标平台，走一遍完整流程，导出 HAR

先把 HAR 丢进 Windsurf 里过一遍 — 几百个请求里找关键路径，这个真的比人快

HAR 不够就看 JS — HAR 只有 HTTP 请求，客户端逻辑（deep link 怎么拼、参数名叫什么）得拉 JS bundle 看

逐步固化 — 跑通一步就锁住，不然很容易把之前已经跑通的代码又改坏（这个是血的教训）

纯协议优先，浏览器兜底 — 能不开浏览器就不开，速度快一个量级，也好批量

另外有个小技巧：Windsurf 的 protobuf 接口没有用标准的 gRPC，而是直接 HTTP POST + Content-Type: application/proto，所以不需要 protoc 生成代码，手动拼 wire format 就行。我写了一套轻量的 protobuf 编解码（_field_string、_field_varint、parse_proto），大概 100 行代码，够用了。
